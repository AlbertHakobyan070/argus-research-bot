# Argus v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Argus to v4: engines swappable per agent role and per transcriber with per-call provenance, a per-run tunable `RunConfig`, Trust → Depth → Insight research upgrades measured by bench v2, a cancellable run driver with a live progress card, and a Telegram Mini App console.

**Architecture:** The v3 LangGraph topology and its two static HITL gates stay; v4 adds an `analyst` node and a bounded `panel → research` gap edge. A process-level engine registry resolves role bindings into an `EnginesSnapshot` kept inside a checkpointed `RunConfig`, so a resumed run reuses its engines. `bot.py` becomes a package whose run driver publishes LangGraph `updates`/`custom` events to an in-process bus, read by the Telegram progress card and by an aiohttp Mini App served through a cloudflared quick tunnel.

**Tech Stack:** Python 3.12 venv, LangGraph 1.2.8, langchain-openai 1.3 (one OpenAI-compatible driver for every provider), python-telegram-bot 22.8, pydantic 2, aiosqlite, aiohttp 3.14, trafilatura 2.3, pypdf 6, faster-whisper 1.2, ReportLab, a no-build ES-module frontend from the arsenal web-ui kit.

**Spec:** `docs/argus-v4-design.md` is the binding authority. Each task names the spec sections it implements; those sections hold the exact contracts, values, owned-file lists and test lists, and the implementer reads them before coding. Where this plan and the spec disagree, the spec wins.

## Global Constraints

- Packages only via `uv pip install` into `./venv` (run from the repo root; never system Python). Allowed new dependencies: `aiohttp>=3.14,<4`, `trafilatura>=2.3,<3`, `pypdf>=6,<7` — nothing else without the orchestrator.
- Never invent a package, API or setting: confirm it in the installed venv (`inspect`), on PyPI or in official docs; say so when unsure.
- Raise errors explicitly. No swallowed exceptions. No new fallback unless it is declared in config, visible to the user, and recorded in run provenance (`errors` + `model_calls`).
- Suite: `PYTHONPATH="" ./venv/Scripts/python.exe -m pytest -q` from the repo root stays green after every task (baseline when this plan starts: 495 passed, 1 skipped).
- Scripts that print LLM text are run with `PYTHONIOENCODING=utf-8`.
- Never start the Telegram bot (`scripts/run.sh`, `python -m argus.bot`): one long-poller per token; the orchestrator runs every live bot check.
- Live network calls (FreeLLMAPI, Exa, arXiv, DDGS, GitHub) only where a step says so; unit tests mock them. Exa spends monthly credit; FreeLLMAPI allows 120 requests/minute.
- Bot contract: plan gate detected as `snap.next == ("research",)`, report gate as `("deliver",)`; per-run threads `tg:<chat_id>:<run8>`; `review_verdict` keeps being written.
- State keys and model fields: only the additions in spec §2.4, added by Task 5; `graph/state.py` is frozen after Task 5.
- The spec §2 contracts (roles, engines schema, LLM facade, RunConfig, event bus, evidence.json, Mini App API) are frozen; changes need the orchestrator.
- Writers emit plain markdown; JSON outputs stay small and are parsed through `graph/jsonx.py`.
- Portability: a POSIX branch wherever the OS matters; no new Windows-only paths.
- Docs describe structure and never hardcode counts or versions.
- Commits: subject `feat(argus-v4): <WP-id> — <title>`, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Each task writes or extends `docs/v4-notes/<wp>.md` (what changed, behaviour changes for handoff.md, new env vars, verification evidence).
- Mocking rule: patch a name where it is looked up (the calling module), not where it is defined.

## Review Focus

1. **A pre-v4 checkpoint resumed through any entry point** (Approve on an old plan message, `/continue`, report Send/Extend/Revise) gets `RunConfig.legacy()` injected visibly and continues; it never crashes on a missing key. Test in Task 5.
2. **Untagged reasoning text instead of JSON on a JSON role** (rerouted gpt-oss models): the `validate` hook fails, one "Reply with only the JSON object." retry follows, then the next fallback, then the declared `on_exhausted`; never an unhandled exception and never a silent empty result. Test in Task 4.
3. **No intel-stack and no Exa text** (fresh box or the MacBook): non-Exa sources are still fetched by the `native` rung, and a source no rung can fetch is reported with the rungs tried, never silently dropped. Test in Task 6.
4. **Hostile fetched content in report HTML** (`<script>`, `onerror=`, `javascript:` links, raw HTML inside markdown) shown in the Mini App: the sanitiser strips it, and `[n]` citation wrapping still works outside code. Test in Task 11.
5. **Cancel while a node is busy** (fetch/digest pools running): the driver task ends at the next node boundary, the run is `cancelled`, the checkpoint is the last completed node, and `/continue` resumes to completion. Test in Task 10.
