# Argus v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Argus to v4: engines swappable per agent role and per transcriber with per-call provenance, a per-run tunable `RunConfig`, Trust → Depth → Insight research upgrades measured by a deterministic bench v2 against a v3 baseline, a cancellable (drain-based) run driver with a live progress card, and a Telegram Mini App console.

**Architecture:** The v3 LangGraph topology and its two static HITL gates stay; v4 adds an `analyst` node and a bounded, targeted `panel → research` gap edge. A process-level engine registry (async-safe; schema validation at startup, model/key validation at run start) resolves role bindings into an `EnginesSnapshot` kept inside a checkpointed `RunConfig`, so a resumed run reuses its engines. `bot.py` becomes a package whose run driver (plain asyncio tasks, one live drive per run, `RunControl` drain for cancel) publishes LangGraph `updates`/`custom` events to an in-process bus, read by the Telegram progress card and by an aiohttp Mini App served through a supervised cloudflared quick tunnel.

**Tech Stack:** Python 3.12 venv, LangGraph 1.2.8 (`RunControl`, `GraphDrained`, `durability`), the `openai` SDK called directly as the one OpenAI-compatible driver (no `ChatOpenAI`), python-telegram-bot 22.8, pydantic 2, aiosqlite, aiohttp 3.14, trafilatura 2.3, pypdf 6, faster-whisper 1.2, ReportLab, a no-build ES-module frontend from the arsenal web-ui kit (no inline script).

**Spec:** `docs/argus-v4-design.md` (Phase E — final, Fable 5.1) is the binding authority. Each task names the spec sections it implements; those sections hold the exact contracts, values, owned-file lists and test lists, and the implementer reads them before coding. Where this plan and the spec disagree, the spec wins.

## Global Constraints

- Packages only via `uv pip install` into `./venv` (run from the repo root; never system Python). Allowed new dependencies: `aiohttp>=3.14,<4`, `trafilatura>=2.3,<3`, `pypdf>=6,<7` — nothing else without the orchestrator. The Task 1 fix round pins `langgraph>=1.2.8,<2` and declares `openai>=2.44,<3` (already installed through langchain-openai; the driver imports it directly).
- Never invent a package, API or setting: confirm it in the installed venv (`inspect`), on PyPI or in official docs; say so when unsure.
- Raise errors explicitly. No swallowed exceptions. No new fallback unless it is declared in config (`on_exhausted` = `degrade` / `skip_item`), visible to the user (report degradation notes, preview quality line, banner) and recorded in run provenance (`errors` + `model_calls`). `ALL_SKIPPED_RAISES` per spec §2.3: every section or every extraction skipped → the node raises; digest raises only when the node ends with no evidence; a run that skipped half or more of a per-item role's items, or left any finding unjudged, is marked degraded (banner, preview line, `metadata.json["degraded"]`) — never shown as a plain `ok`.
- Suite: `PYTHONPATH="" ./venv/Scripts/python.exe -m pytest -q` from the repo root stays green after every task (baseline count in spec Appendix B).
- Scripts that print LLM text are run with `PYTHONIOENCODING=utf-8`.
- Never start the Telegram bot (`scripts/run.sh`, `python -m argus.bot`): one long-poller per token; the orchestrator runs every live bot check.
- Live network calls (FreeLLMAPI, Exa, arXiv, DDGS, GitHub) only where a step says so; unit tests mock them. Exa spends monthly credit. **Nothing on the bot's startup path may call the LLM proxy** (media and `/find` must work with it down).
- Bot contract: plan gate detected as `snap.next == ("research",)`, report gate as `("deliver",)` — **only valid when the run has no live drive** (in-flight registry); per-run threads `tg:<chat_id>:<run8>`; `review_verdict` keeps being written.
- State keys and model fields: only the additions in spec §2.4, added by Task 5; `graph/state.py` is frozen after Task 5.
- The spec §2 contracts (roles, engines schema, LLM facade, RunConfig, run lifecycle + bus, evidence.json, Mini App API, node-level contracts) are frozen after the Task 1 fix round; changes need the orchestrator.
- Writers emit plain markdown; JSON outputs stay small and are parsed through `graph/jsonx.py` via the `validate` hook of `llm.complete`.
- Portability: a POSIX branch wherever the OS matters; no new Windows-only paths; subprocesses use `start_new_session=True` on POSIX.
- Docs describe structure and never hardcode counts or versions (dated facts live only in spec Appendix B).
- Commits: subject `feat(argus-v4): <WP-id> — <title>`, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Each task writes or extends `docs/v4-notes/<wp>.md` (what changed, behaviour changes for handoff.md, new env vars, test files touched, verification evidence).
- Mocking rule: patch a name where it is looked up (the calling module), not where it is defined.
- Test helpers live in `tests/helpers.py` (`from helpers import make_run_config, fake_engines_snapshot`); never import `conftest`.

## Review Focus

1. **A pre-v4 checkpoint resumed through any entry point** (Approve on an old plan message, `/continue`, report Send/Extend/Revise) gets `RunConfig.for_legacy_checkpoint(engines, length=<checkpoint length>)` injected visibly and continues; it never crashes on a missing key, and `require()` rejects a config whose `length` disagrees with the state. Test in Task 5.
2. **Untagged reasoning text instead of JSON on a JSON role** (rerouted gpt-oss models): the `validate` hook fails, one "Reply with only the JSON object." retry follows, then the next fallback, then the declared `on_exhausted`; never an unhandled exception and never a silent empty result. Test in Task 4.
3. **No intel-stack and no Exa text** (fresh box or the MacBook): non-Exa sources are still fetched by the `native` rung, and a source no rung can fetch is reported with the rungs tried, never silently dropped. Test in Task 7.
4. **Hostile fetched content in report HTML** (`<script>`, `onerror=`, `javascript:` links, raw HTML inside markdown) shown in the Mini App: the sanitiser strips it, `[n]` citation wrapping still works outside code, and the CSP `script-src` never contains `'unsafe-inline'`. Test in Task 11.
5. **Cancel while a node is busy** (fetch/digest pools running): `cancel_run` calls `RunControl.request_drain`; `research_node` submits no new fetch, digests what it fetched and returns its partial update with a `cancelled:` error line (spec §2.5); any other node finishes; the drive ends with `GraphDrained` at the superstep boundary, the checkpoint is saved with `next` naming the following node, the run is `cancelled`, the card showed "cancelling — finishing the current step", and `/continue` resumes to completion. `task.cancel()` fires only after the drain timeout (default 300 s) and is logged. Tests in Task 7 (node side) and Task 10 (driver side).
6. **Every finding is judged**: the grounding judge runs in batches grouped by section, each batch sees exactly its cited notes with full quotes within the input budget, `PanelVerdict.judged == total`, and a batch that is skipped, fails or returns unparseable JSON counts its findings as unjudged (never as passed), producing the "⚠ Not fact-checked" banner and `judged < total` (an acceptance failure in the live check). Test in Task 9.
7. **SSRF and size guards on the native fetcher**: URLs resolving to loopback, private or link-local addresses (incl. the proxy's and console's ports) are refused with a recorded reason; downloads stop at `FetchConfig.max_bytes`. Test in Task 7.
8. **Two approvals race** (chat and console on the same run): exactly one drive starts; the other gets `already_running`; `awaiting` is false while the drive runs. Test in Task 10.
