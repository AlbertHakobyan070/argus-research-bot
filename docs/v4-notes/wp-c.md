A range is expanded only when it is at most 20 wide (`[1-21]`, `[1-40]` and `[2019-2020]` stay as written), and an id list holding a 0 (`[0, 1]`) stays. Never touched (fix round 1): code — fences (backtick or `~~~`, an unterminated one to the end), indented blocks (after a blank line, not a list's continuation), spans of any backtick run — link and image destinations and their bracketed text, bare URLs (`https?://\S+`) and footnote definition lines (`[^2]: …`). ### Decisions where the spec is silent

- **Dedupe is cross-section only** (as `cross_section_duplicate_ratio` measures it). A repeat inside one section is the writer's style, and its sentence often backs another finding.
- **The merge neighbour is the nearest surviving section** (previous first). Since fix round 1 the outline is rewritten (the merge sticks) — also when the neighbour's merged re-write is skipped: the neighbour then owns the merged sub-questions and notes, and its next re-write in the round writes them.
- **The flat writer's notes are every usable note** (`note_ids=None`): flat lengths have no outline to allocate; it has the sections' 24 000-char budget.
- **Extraction ids**: the sentence's markers that the model's `source_ids` name; when the model names none of them, every marker of the sentence (the sentence is what the reader sees and what the cut locates — never a finding without ids for a sentence that cites).
- **The rewrite ratio's denominator is `judged`**, so a half-skipped judge cannot dilute a real flag rate.
- **A judge reply without a `flagged` list is unparseable** — never "nothing flagged" (the v3 failure mode).
- **The diversity rerun reruns every batch** and counts only when it judged at least as many findings; its events are not re-emitted.
- **report_builder recomputes the uncited specifics over the cut body** (the reader's text); the panel's `uncited_specifics` is the pre-cut metric.
- **TL;DR**: with an analysis, its takeaways, in the analyst's order, each still contained (normalised) in the cut analysis and kept (R2 at `b34aae8`): the analysis findings stating it — a sentence contained in the takeaway or the takeaway in it, or a claim that `twins` it (the takeaway's `source_ids` for rule (ii)) — are all `kept`, and there is at least one (a takeaway no finding states was never judged); without one, or with no takeaway kept (R2 at `9b7e012`: e.g. the analysis extraction skipped), the first kept finding of each section whose sentence is contained (normalised) in the cut section — never a fuzzy match (R2 at `46191fa`). An analysis left unjudged is still named in "⚠ Not fact-checked". A run without sections (no usable evidence) has no TL;DR and no omission line.
- **`degraded`** = the degraded-run banner, any unjudged finding or any unjudged section (a section or the Analysis citing `[n]` with no finding). Grounding switched off shows "⚠ Not fact-checked — the grounding judge is off" but is a configuration, not a degradation; with it off no section is called unjudged.
- **The degraded-run banner** counts per per-item role (`research.digest`, `compose.section`, `compose.findings_extract` over the whole run; `panel.grounding` over its last panel pass — the panel verdict's skipped batches of `judge_verdicts["grounding_batches"]`): items = its ok records (diversity reruns excluded) plus its `skip:` lines; the reason is "unparseable", else the 429/5xx code, else the error type. The coverage review is a single-call role: its skip is a degradation note only.
- **The stricter verdict** (R1 at `46191fa`) applies to the findings the verdict cuts — flagged or citing unknown ids only — one level deep, before locating. Since fix round 3 (R1 at `9b7e012`, replacing fix round 2's number tokens) a twin is (i) the dedupe normalisation (`claim_norm`) at 0.85 with the same numeric values, or (ii) the same ≥ 2 values and a shared source, and never a claim and its negation — so the live q013 restatement (similarity 0.68, the same four values, source [4]) is a twin by (ii), and a digit in a name no longer counts ("GPT-4" contributes nothing: the round-1 q013 fixture's "… than GPT-4" claim twins its analysis restatement again, by (i)). A kept twin is located and cut like any other (its own row, reason `near-duplicate of cut f<n>`).
- **Numeric values compare as `Decimal`** (fix round 3; the spec says "by value"): `2.50` = `2.5`; a dotted run that is no decimal (`3.10.2`, a decimal comma `2,5`) compares as written. A sign is not part of a value (R1's pattern has none): `-5%` and `5%` carry the same value.
- **The negator check reads quote verification's fold**, so `don’t` (curly apostrophe) and `can't` are negators as `dont` / `cant`; both claims negated is no mismatch.
- **The rename remap drops a changed title that names no outline section** ("`changed_sections` names only existing titles", fix round 3); a title that is in the outline maps to its merged survivor.
- **A footnote definition's continuation** (fix round 3) is the non-blank lines indented by a space or a tab right below it (or below another continuation line); a blank line ends it, so an indented paragraph after a blank line (a multi-paragraph footnote) stays — `_code_lines` reads it as code.
- **A finding stated in a cut span** is one whose located sentences all lie inside the section's cut sentences and whose sentence no longer occurs (normalised containment) in the cut body; its reason joins the row of the span that cut its first sentence.
- **A section the dedupe empties** (fix round 2) merges into its neighbour in the returned outline only: the neighbour is not written again this run, and its section keeps the `note_ids` it was written from; the outline carries the merged sub-questions and notes for its next re-write.
- **The flat writer rejects a JSON object** (fix round 2): the brief's probe case (a too-short reply, then a JSON reply) must not ship JSON as the body even when the model ignores the markdown nudge, so `_flat_body` fails a reply that parses as a JSON object — retried, then the role raises.
- **Footnote definitions are removed from every writer's reply**: compose's sections and flat body, and since fix round 3 the analyst's (an approved edit to WP-I's `insight.py`), each a `cite:` line; a reply that is not written (a skipped section, a degraded analysis) records none.
- **An unknown id beside known ones** is judged per sentence: a kept sentence citing a known id loses its unknown ones; a sentence citing unknown ids only stays (the unknown-id rule cuts it when a finding states it).
- **Degradation notes** show the bench's `skip:` / `degrade:` / `legacy:` lines plus `pdf:`, `tldr:`, `cancelled:`, `compose:` (a merge that lost notes) and `cite:` (fix round 2: an unknown id stripped, a footnote definition removed) — the visible losses and repairs. `analysis:` lines (pointer 20) are informational: they stay in `errors` and evidence.json `errors`, not in the notes, `warnings` or `degradations`. evidence.json `degradations` and metadata.json `degradations` are exactly the bench set.
- **The citation-integrity passes run over the report up to Sources**, not over the degradation notes, the footer or the lecture appendix: a note naming a source that could not be digested keeps its URL.
- **The title block's `findings:` count is the kept findings.**
- **WP-0 decision 6 is superseded**: the flat writer no longer emits headings of its own, so the flat path is on `assemble_draft` (`## Findings`). (Its stated reason was also off for `tldr`: `TLDR_SYSTEM` always wrote a bare paragraph; only `FLAT_SYSTEM` — `short` and one-sub-question briefs — emitted `## TL;DR` / `## Key Findings`.)
