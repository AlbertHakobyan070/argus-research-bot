## 1. Target architecture

### 1.1 Graph (v4)

```
intake → brief → scout ═╣ PLAN GATE (interrupt_after=["scout"]) ╠═ research → outline → compose → analyst → panel
                                                                       ▲                                      │
                                                                       └──── gap research (targeted, bounded) ┤  panel_verdict.next == "research"
                                                           compose ◄──── targeted rewrite (bounded) ──────────┤  panel_verdict.next == "compose"
report_builder ═╣ REPORT GATE (interrupt_before=["deliver"]) ╠═ deliver → END | extend_prep → research | revise_prep → compose
quick path unchanged: intake → quick_answer → deliver
```
Changes vs v3: one new node `analyst` (Insight), one new conditional target `panel → research` (coverage gaps go back to a **targeted** gap-research wave, then an **extend-mode** outline that keeps existing sections and allocates the new notes, then compose rewrites **only the sections whose allocated note set changed**, then analyst → panel), `route_after_panel` reads a precomputed `panel_verdict["next"]`. Gate detection by the bot stays `snap.next == ("research",)` and `("deliver",)`. Nodes stay sync functions; internal parallelism stays `ThreadPoolExecutor`. All bot/bench `astream` calls pass `durability="sync"` and `stream_mode=["updates","custom"]`.

### 2.3 LLM facade — `llm.py` (WP-A)

```python
@dataclass
class CallRecord:                       # model_dump() → flat dict appended to state["model_calls"] (reducer operator.add)
    role: str; tier: str; profile: str; provider: str
    requested_model: str; served_model: str; routed_via: str        # routed_via from body "_routed_via"/"x_groq" or header x-routed-via, else ""
    served_provider: str = ""           # kept for v3 readers (== routed_via's provider segment)
    attempt: int = 1; fallback_rank: int = 0; ok: bool = True; error: str = ""
    latency_ms: int = 0; prompt_tokens: int = 0; completion_tokens: int = 0; reasoning_tokens: int = 0
    finish_reason: str = ""; json_mode: bool = False
    retry_reason: str = ""              # "transient" | "truncated" | "unparseable" | "diversity_rerun"
    item: str = ""                      # per-item label (source url / section title / judge name)
    cached: bool = False; extra: dict = field(default_factory=dict)

@dataclass
class LLMResult: text: str; parsed: Any; record: CallRecord; records: list[CallRecord]   # records = every attempt incl. failed fallbacks; parsed = validate(text) or None

class EngineError(RuntimeError): role: str; attempts: list[CallRecord]          # on_exhausted == "raise"
class EngineSkipped(EngineError): ...                                            # on_exhausted == "skip_item" — caught only by per-item call sites
class EngineDegraded(EngineError): degradation: str                             # on_exhausted == "degrade" — caught only by the owning node, which applies the named degradation

def complete(role: str, messages: list[BaseMessage], *, engines: EnginesSnapshot,
             temperature: float | None = None, max_tokens: int | None = None,
             json_mode: bool | None = None, expect_json: bool | None = None,
             validate: Callable[[str], Any] | None = None, item: str = "") -> LLMResult
```
Semantics: binding = `engines.roles[role]` (`KeyError` → `ValueError("role not bound")`); `json_mode` default = `role in JSON_ROLES and provider.supports_json_mode`; `expect_json` default = `role in JSON_ROLES`. Driver call via `engines/llm_openai.py::OpenAICompatDriver.complete(engine, provider, messages, temperature, max_tokens, json_mode) -> DriverResponse(text, served_model, routed_via, finish_reason, usage, raw)` wrapping `ChatOpenAI(base_url, api_key, model, timeout, default_headers, extra_body)`; `supports_temperature=False` → omit `temperature` (never send `top_p`). Transient retry policy = today's (3 attempts, transport/timeout/5xx/429 only, `retry_reason="transient"`). Then `strip_reasoning(text)` removes `<think>…</think>`, `<thinking>…</thinking>`, `<reasoning>…</reasoning>`, `<analysis>…</analysis>` blocks (case-insensitive, DOTALL) — nothing else. If `expect_json` and `finish_reason == "length"` and `retry_on_truncation` → one retry with `max_tokens*2` (cap 4096), `retry_reason="truncated"`. **Validation:** when `validate` is given (JSON roles pass their `jsonx.parse_json_obj(..., require_any=…)` closure), `complete` calls it; on exception → one retry on the **same** engine with the appended human message `"Reply with only the JSON object."` (`retry_reason="unparseable"`) → still failing → next fallback → then `on_exhausted`. This, not `strip_reasoning`, is what handles untagged reasoning prose from rerouted `gpt-oss` models. On non-transient failure or exhausted retries → next fallback (`fallback_rank+1`, each attempt recorded); when all fail: `raise` → `EngineError`; `skip_item` → `EngineSkipped` (caught only by per-item call sites: record `"skip: <role> <item> (<reason>)"` in `errors`, records in `model_calls`); `degrade` → `EngineDegraded(degradation=DEGRADABLE_ROLES[role])` (caught only by the owning node, which applies exactly that degradation and records `"degrade: <role> → <degradation> (<reason>)"`). Client cache per `(provider, model, temperature, max_tokens, json_mode)`. `rpm_limit` → per-provider token bucket (thread-safe; nodes call from pools).
`engines` argument: real roles pass `RunConfig.require(state).engines` (checkpointed snapshot); during Phases 1–2 the wrappers `chat_for_tier`/`invoke_with_retry`/`record_from_response` route through `complete` with `role=f"legacy.{tier}"` and `engines=registry.active_snapshot()` (process-level, refreshed on `/engines` changes). `resolve_snapshot` emits the `LEGACY_ROLES` bindings (= the profile's tier `EngineSpec`, `on_exhausted="raise"`); `/engines tier` therefore also fixes them. WP-B/WP-I/WP-C move every node to a real role id; WP-H deletes the wrappers and `LEGACY_ROLES`.
Registry (`engines/registry.py`): `load_config(paths, library) -> EnginesConfig`; `resolve_snapshot(cfg, profile_name) -> EnginesSnapshot` (model resolution: fixed id → as is; `model_from_preferences` → first id present in the provider's live `/models` list (TTL 600 s cache; `force` refresh available), else `"auto"` if listed, else unresolved; `models_endpoint False` → id must be in `known_models`; fallback drop rule and `warnings` per §2.2); `validate_active(cfg) -> EnginesSnapshot` (raises `EngineConfigError`); `active_snapshot() -> EnginesSnapshot` (cached; invalidated by `set_active_profile`/`set_overrides`); `set_active_profile(name)`, `set_overrides(profile, ProfileOverrides)`, `set_transcriber(TranscriberConfig)` (persist to library + re-validate; errors propagate to the caller unchanged); `live_models(provider) -> list[str]`; `family(model_id) -> str` (strip path prefixes `@cf/`, `openai/`, `meta-llama/`, `google/`, … then prefix table: claude→anthropic; gpt/o1/o3/o4/gpt-oss→openai; gemini/gemma→google; llama/meta→meta; qwen→qwen; deepseek→deepseek; mistral/ministral/codestral/magistral/devstral→mistral; nemotron→nvidia; glm/z-ai→zhipu; kimi/moonshot→moonshot; command→cohere; cogito→deepcogito; minimax→minimax; granite→ibm; phi→microsoft; else first token).
Provenance summary (`engines/registry.py::summarize_calls(model_calls, errors=None) -> dict`): `{profile, calls: n, by_role: {role: {n, served_models: {id: n}, fallbacks: n, skipped: n, degraded: n, errors: n, truncation_retries: n, unparseable_retries: n, avg_latency_ms}}, reroute_rate, judge_families, writer_families, judge_writer_same_family: bool, warnings: [...], degradations: [...]}` (`degradations`/`skipped` read the `degrade:`/`skip:` prefixed error strings) — written to `metadata.json["engines"]` (WP-A edits `report_builder_helpers.build_sidecar_metadata` to add it), `evidence.json["engines"]`, one title-block line and the preview quality line.

```python
    def exa_cost_estimate_usd(self) -> float                 # searches*price_per_search + (searches*num_results + max_contents_pages)*price_per_page, shown as "≈"
def require(state: Mapping) -> RunConfig                     # ValueError("state['run_config'] missing — every entry point must set it") if absent/invalid
async def ensure_in_checkpoint(graph, cfg, *, engines) -> RunConfig   # aget_state; if run_config missing → aupdate_state({"run_config": RunConfig.legacy(engines).model_dump(), "errors": ["legacy: run_config defaults applied (pre-v4 checkpoint)"]}); returns the config
```
**One run_config rule for every node:** nodes read `rc = run_config.require(state)` (never `state.get`), so a missing key fails loudly. Every **new** run sets it (bot `/research`+`/ask`, webapp `POST /api/runs`, `bench/runner.py`, `scripts/live_check.py`, `tests/manual_e2e.py`, `scripts/demo_run.py`); every **resume** entry point (plan approve, plan edit, report revise/extend/send, `/continue` re-attach and extend fork) calls `ensure_in_checkpoint` first — the legacy injection is recorded in `errors`, in provenance (`origin="legacy"`) and in the report's degradation notes. Tests build configs with `tests/conftest.py::make_run_config(length="short", depth=None, **overrides)` (WP-0; uses a stub `EnginesSnapshot` bound to a fake provider).

Presets (`PRESETS: dict[Depth, dict]`; the bench tunes them, these are the shipped defaults). `total_fetch_cap` and `exa.max_searches` **include** the gap reserve, so the first pass keeps full depth (first pass = `total_fetch_cap − gap_waves_max × gap_fetch_per_wave`; Exa first pass = `max_searches − gap_waves_max × 2`):

| knob | quick | standard | deep | exhaustive |
|---|---|---|---|---|
| research.waves / fetch_per_wave | 1 / 10 | 3 / 14 | 4 / 16 | 5 / 20 |
| total_fetch_cap (= first pass + reserve) | 12 (12 + 0) | 48 (32 + 16) | 78 (48 + 30) | 108 (72 + 36) |
| gap_fetch_per_wave / gap_waves_max | 0 / 0 | 8 / 2 | 10 / 3 | 12 / 3 |
| per_subq_target / coverage_min_strong | 2 / 1 | 3 / 2 | 4 / 3 | 5 / 3 |
| digest_chunks_long_doc / writer_min_relevance | 1 / 2 | 2 / 3 | 3 / 3 | 4 / 3 |
| search.exa.max_searches (= first pass + reserve) / max_contents_pages | 6 (6 + 0) / 12 | 16 (12 + 4) / 40 | 26 (20 + 6) / 64 | 36 (30 + 6) / 96 |
| panel.grounding / coverage / precision_mode | on / off / deterministic | on / on / deterministic | on / on / deterministic | on / on / deterministic |
| panel.max_compose_revisions | 0 | 1 | 1 | 2 |
| compose.analyst | on unless length=tldr | on | on | on |

**Budget semantics (Depth, Trust):** the first research pass (scout + waves) spends at most `first_pass_fetch_cap()` fetches and `max_searches − exa_search_reserve()` Exa searches; gap waves spend the reserve (`gap_fetch_per_wave` fetches and 2 Exa searches each); a user **Extend** gets a fresh allowance on top (`fetch_per_wave` fetches, `exa.max_searches // waves` searches), recorded in `search_spend["extend_allowances"]`; **pinned local appends (`/append`) bypass every cap and are always ingested** — this fixes the v3 Trust bug where a capped run (`room <= 0`) silently skipped appended sources while `continue_cmd` marked them "ingested". Compose bookkeeping: `compose_runs` counts every compose execution, `revision_rounds` counts panel-triggered rewrites; invariant `compose_runs ≤ 1 + gap_waves_max + max_compose_revisions`.

**State additions (`graph/state.py`, WP-D only; frozen afterwards):** `run_config: dict`, `search_spend: dict` (`{exa_searches, exa_text_pages, exa_contents_pages, exa_usd, arxiv_queries, ddgs_queries, github_queries, extend_allowances: int, recency: {...}|None}`), `analysis: dict | None`, `tldr_md: str | None`, `coverage_gaps: list[int]`, `gap_waves: int`, `compose_runs: int`, `cancel_note: str`. `report_paths` gains key `"evidence"`. ### 2.5 Progress event bus — `bot/progress.py` (WP-E1 owns; WP-E2 consumes)

```python
@dataclass(frozen=True) class RunEvent: seq: int; ts: float; run_id: str; kind: str; node: str; data: dict
class RunEventBus:
    def publish(self, run_id: str, kind: str, node: str, data: dict) -> RunEvent      # seq increments per run
    def since(self, run_id: str, after: int, limit: int = 200) -> list[RunEvent]
    def last_seq(self, run_id: str) -> int
    def subscribe(self, run_id: str) -> asyncio.Queue[RunEvent]; def unsubscribe(...)
    def finish(self, run_id: str) -> None     # keeps the buffer 1 h, then drops (ring buffer maxlen 500 per run)
```
Event kinds and `data` shapes: `stage` `{status:"start"|"end"|"error"|"cancelled", summary:{…node-specific counts…}}` (emitted by the driver from LangGraph `updates` for `end`, and by nodes via `get_stream_writer()` for `start`); `search` `{wave, mode:"first"|"gap"|"extend", queries, hits, errors:[str]}`; `fetch` `{url, ok, fetcher, ms, pinned}`; `digest` `{source_id, ok, relevance, cached}`; `rerank` `{wave, candidates, kept}`; `section` `{title, ok, chars, reused}`; `analysis` `{takeaways, has_disagreement, has_scenarios}`; `judge` `{name, verdict, skipped}`; `degrade` `{role, degradation, reason}`; `gate` `{kind:"plan"|"report"}`. Nodes emit custom events with `writer = get_stream_writer()` **obtained and called only in the node's own thread** (pool threads do not inherit the LangGraph context var); results from pools are emitted as their futures complete. The driver maps `("custom", payload)` → `publish(run_id, payload["event"], payload.get("node",""), payload)` and `("updates", {node: delta})` → `stage end` with a deterministic summary per node.
