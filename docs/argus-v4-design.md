## 1. Target architecture

### 1.1 Graph (v4)

```
intake → brief → scout ═╣ PLAN GATE (interrupt_after=["scout"]) ╠═ research → outline → compose → analyst → panel
                                                                       ▲                                      │
                                                                       └──── gap research (targeted, bounded) ┤  panel_verdict.next == "research"
                                                           compose ◄──── targeted rewrite (bounded) ──────────┤  panel_verdict.next == "compose"
report_builder ═╣ REPORT GATE (interrupt_before=["deliver"]) ╠═ deliver → END | extend_prep → research | revise_prep → compose
quick path unchanged: intake → quick_answer → deliver
```
Changes vs v3: one new node `analyst` (Insight), one new conditional target `panel → research` (coverage gaps go back to a **targeted** gap-research wave, then an **extend-mode** outline that keeps existing sections and allocates the new notes, then compose rewrites **only the sections whose allocated note set changed**, then analyst → panel), `route_after_panel` reads a precomputed `panel_verdict["next"]`. The TL;DR is assembled **deterministically after the cuts** in `report_builder` (§2.8, R2). Gate detection by the bot stays `snap.next == ("research",)` and `("deliver",)`, **valid only when no live drive holds the run** (§2.5 invariant). Nodes stay sync functions; internal parallelism stays `ThreadPoolExecutor`. All bot/bench `astream` calls pass `durability="sync"`, `stream_mode=["updates","custom"]` and a `control=RunControl()` handle used for cancellation (drain at the superstep boundary; `research` additionally stops between pool items, §2.5).

### 2.3 LLM facade — `llm.py` and `engines/llm_openai.py` (WP-A)

```python
@dataclass
class CallRecord:                       # dataclasses.asdict() → flat dict appended to state["model_calls"]
    role: str; tier: str; profile: str; provider: str
    requested_model: str; served_model: str; routed_via: str        # routed_via from headers (x-routed-via) or body (_routed_via / x_groq), else ""
    served_provider: str = ""           # v3-compatible (provider segment of routed_via)
    attempt: int = 1; fallback_rank: int = 0; ok: bool = True; error: str = ""
    latency_ms: int = 0; prompt_tokens: int = 0; completion_tokens: int = 0; reasoning_tokens: int = 0
    finish_reason: str = ""; json_mode: bool = False
    retry_reason: str = ""              # "transient" | "timeout" | "retry_after" | "truncated" | "unparseable" | "diversity_rerun"
    item: str = ""; cached: bool = False; extra: dict = field(default_factory=dict)

NOT_VALIDATED = object()                # sentinel: LLMResult.parsed when no validate() was given (never None-for-falsy)
@dataclass
class LLMResult: text: str; parsed: Any; record: CallRecord; records: list[CallRecord]

class EngineError(RuntimeError): role: str; attempts: list[CallRecord]
class EngineSkipped(EngineError): ...   # on_exhausted == "skip_item" — caught only by per-item call sites
class EngineDegraded(EngineError): degradation: str   # on_exhausted == "degrade" — caught only by the owning node
class EngineConfigError(RuntimeError): ...

def complete(role: str, messages: list[BaseMessage], *, engines: EnginesSnapshot,
             temperature: float | None = None, max_tokens: int | None = None,
             json_mode: bool | None = None, expect_json: bool | None = None,
             validate: Callable[[str], Any] | None = None, item: str = "") -> LLMResult
```
**Driver (`engines/llm_openai.py::OpenAICompatDriver`)** calls the `openai` SDK directly (no `ChatOpenAI`): `openai.OpenAI(base_url, api_key, timeout=provider.timeout_s, max_retries=0, default_headers=provider.headers)` — `api_key` is **never `None`**: a keyless provider (`api_key_env` is None) gets the placeholder string `"none"` (verified: with `None` the SDK raises "Missing credentials" without `OPENAI_API_KEY`, and with that variable set it sends the OpenAI key to whatever `base_url` is configured), `client.chat.completions.with_raw_response.create(model=…, messages=<BaseMessage→dict mapper: system/user/assistant>, **{provider.token_param: max_tokens}, temperature=… only when supports_temperature, response_format={"type":"json_object"} only when json_mode, extra_body={**provider.extra_body, **engine.extra_body})`. From the raw response it records headers (`x-routed-via`, `retry-after`, `x-ratelimit-*`), body `_routed_via`/`x_groq`, `finish_reason`, `usage` incl. `completion_tokens_details.reasoning_tokens`. The driver interface is a Protocol (`complete(engine, provider, messages, *, temperature, max_tokens, json_mode) -> DriverResponse(text, served_model, routed_via, finish_reason, usage, headers, raw)`) so a native driver can be added later behind `ProviderSpec.kind`.
**Facade semantics:** binding = `engines.roles[role]`; `json_mode` default = `role in JSON_ROLES and provider.supports_json_mode`; `expect_json` default = `role in JSON_ROLES`. Retry policy per attempt: connection errors / 5xx / 429 → up to 3 tries with backoff (`retry_reason="transient"`), honouring `Retry-After` up to `retry_after_cap_s` (`"retry_after"`); a timeout is retried **at most `timeout_retry_max`** times (`"timeout"`); the SDK never retries (`max_retries=0`). Then `strip_reasoning(text)` (tagged `<think>/<thinking>/<reasoning>/<analysis>` blocks only). `expect_json` and `finish_reason == "length"` and `retry_on_truncation` → one retry with `max_tokens*2` (cap 4096, `"truncated"`). `validate` (JSON roles pass their `jsonx.parse_json_obj(..., require_any=…)` closure): on exception → one retry on the same engine with the appended user message `"Reply with only the JSON object."` for a JSON role, or `"Reply with only the complete markdown text."` for a markdown role that validates (e.g. `compose.flat`'s length rule) (`"unparseable"`) → next fallback → `on_exhausted`. `parsed` = the validator's return value, else `NOT_VALIDATED`. Exhaustion: `raise` → `EngineError`; `skip_item` → `EngineSkipped` (per-item call sites record `"skip: <role> <item> (<reason>)"` in `errors`); `degrade` → `EngineDegraded(degradation)` (the owning node applies exactly that degradation and records `"degrade: <role> → <degradation> (<reason>)"`). **`ALL_SKIPPED_RAISES` rule** (the v3 baseline shipped 310–340-char "writer failed" stubs with status `ok` after 14–19 of 28 digests hit 429): `compose.section` — every section skipped → the node raises `EngineError`; `compose.findings_extract` — every section's extraction skipped → raises (nothing could be judged); `research.digest` — raises only when the **node ends with `evidence` empty** (today's `fetched and not evidence` check, now an error, not a note), so a gap wave whose few digests all fail never kills a run that already holds evidence. Any per-item role (invoked once per source, section or judging batch: digest, findings extraction, section writer, grounding batches — grounding counted over its last panel pass only) that skipped **half or more** of its items in a run, or any unjudged finding or unjudged section (a section or the Analysis whose body cites `[n]` but has no findings, named in the banner), marks the run **degraded**; a single-call role's skip (e.g. the coverage review) is a degradation note only: the top-of-report banner (§2.8), the preview quality line and `metadata.json["degraded"] = true`; the library status stays `ok` (the run finished) but is never shown without the mark. Client cache per `(provider, model)`; `rpm_limit` → per-provider token bucket (thread-safe).
**Registry (`engines/registry.py`, async-safe, B7):** `load_config(paths, library) -> EnginesConfig` (async: library is aiosqlite); `validate_schema(cfg)` (sync, startup); `async resolve_snapshot(cfg, profile) -> EnginesSnapshot` (live `/models` via `httpx.AsyncClient` or `asyncio.to_thread`, never on the event loop thread; TTL 600 s cache); `async validate_active(cfg) -> EnginesSnapshot` (run start / switch); `async active_snapshot()` (cached; invalidated by `set_*`); `current_snapshot_cached() -> EnginesSnapshot` (sync; raises `EngineConfigError` if none — used only by the Phase 1–2 wrappers inside a running graph; therefore **every drive entry** — `/research`, `/ask`, `POST /api/runs`, plan approve/edit, report send/extend/revise, `/continue` re-attach and extend fork — first does `await registry.active_snapshot()`, which resolves once and caches, so a parked run resumed after a restart never hits an empty cache); `async set_active_profile(name)`, `async set_overrides(profile, ProfileOverrides)`, `async set_transcriber(cfg)` (persist + re-validate; errors propagate); `live_models(provider)`; `family(model_id)` (prefix table as before); `summarize_calls(model_calls, errors=None) -> dict` (`by_role` with served models, fallbacks, skipped, degraded, logical `calls` = `ok` + `exhausted` (exhausted counted from the facade's "role <id>: every engine failed after <n> attempts" lines in `errors`), attempt records counted apart as `attempts` / `failed_attempts` / `exhausted_attempts`, retries by reason, latency; `reroute_rate`; `judge_families`, `writer_families`, `judge_writer_same_family`; `warnings`; `degradations`; `exa_usd` when given). `resolve_snapshot` also emits the `LEGACY_ROLES` bindings (profile tier specs, `raise`) during Phases 1–2; `/engines tier` fixes them; WP-H deletes the wrappers and `LEGACY_ROLES`.
`engines` argument: real roles pass `RunConfig.require(state).engines`; the wrappers pass `registry.current_snapshot_cached()`.

### 2.5 Run lifecycle, cancellation and the progress bus — `bot/runs.py`, `bot/progress.py` (WP-E1)

**Invariants (R3–R5, R21):**
- **One live drive per run**: `runs.py` keeps an in-flight registry `{run_id: RunHandle(task, control: RunControl, lock: asyncio.Lock, stage, started_at)}`; every action (approve, edit, revise, extend, send, cancel, `/continue`) takes the run's lock and checks the registry first; a second actor gets `409 already_running` (API) / "already running" (chat). `awaiting = gate(snap.next) and run_id not in_flight` — `snap.next` alone is not a gate signal while a drive runs.
- **One executing research at a time** (free-tier limits, Exa budget): a second `start_run`/approve while another run executes returns `409 busy` / "busy — run `<id>` (`<topic…>`) is at `<stage>`; try again when it reaches a gate"; runs waiting at a gate do not count.
- **Untracked gate runs attach on action** (orchestrator ruling, Task 10): a bot restart empties the registry, so an action on a run resting at a gate that is not tracked first **attaches** it — library row → checkpoint → `ensure_in_checkpoint` → its gate → a handle with that gate and the default plan choices, the tapped message becoming the gate message — and then acts; buttons minted before a restart keep working, and the console can act on every run it lists as awaiting. Only a run with no library row, or one not resting at a gate, answers "not in flight … /continue".
- **Drives are plain `asyncio.create_task`** tracked by `runs.py` (never `application.create_task`, whose tasks PTB awaits in `stop()` before `post_stop`); the driver catches and reports its own exceptions (status `error`, message to the chat, `stage error` event).
- **Cancel = drain**: `cancel_run` calls `handle.control.request_drain("user cancel")`; LangGraph raises `GraphDrained` at the next superstep boundary with the checkpoint saved; the driver catches it, sets status `cancelled`, `cancel_note`, publishes `stage cancelled`; the card shows "cancelling — finishing the current step" meanwhile. **`research_node` also stops between pool items** (measured: the v3 medium research node ran 82 s, deeper presets fetch 1.5–2.4× more, and executor threads are joined at interpreter exit, so a boundary-only drain is what makes cancel and shutdown slow): the node declares `runtime: Runtime` (LangGraph injects it; `runtime.drain_requested` is a thread-safe flag read, and the node thread passes `runtime` into its loops — pool threads never call `get_runtime()`); once the flag is set it submits **no new fetch** (`ThreadPoolExecutor.shutdown(cancel_futures=True)` drops the queued ones), still digests what was fetched (nothing fetched is wasted), skips the remaining waves, and returns its normal partial update plus `errors: ["cancelled: research stopped after <k>/<n> fetches in wave <w> (<reason>)"]`; `GraphDrained` then fires at the boundary with `next=("outline",)`. No node-level cancel exception exists: partial evidence is kept and visible (title block, degradation notes); a later **Extend** fetches the sources left unfetched (research already fetches only sources not yet in `fetched`). `compose`/`analyst`/`panel` drain at the boundary (a bounded number of parallel LLM calls). `task.cancel()` is used only after `ARGUS_CANCEL_DRAIN_TIMEOUT_S` (default 300) and is logged as a last resort (it cannot stop a running thread; it only stops waiting). `/continue` on a cancelled run resumes from its checkpoint (`astream(None, …)`) and sets `running`.
- **Shutdown**: a `post_stop` hook (`POST_STOP_HOOKS`) requests drain on every live drive, awaits them with a bound (`ARGUS_SHUTDOWN_DRAIN_S`, default 120), then cancels what remains; `post_shutdown` closes saver/library/webapp/tunnel as today.

### 2.8 Node-level contracts (WP-B/WP-I/WP-C)

- `engines/urls.canonical_url(url) -> str`: lowercase host, strip `www.`, default ports, trailing slash, `#fragment`, tracking params (`utm_*`, `ref`, `fbclid`, `gclid`); `http`→`https`; `export.arxiv.org`→`arxiv.org`; arXiv `abs|pdf|html` + version and `ar5iv`, `huggingface.co/papers/<id>` → `https://arxiv.org/abs/<id>`; IPv6 hosts keep their brackets; a malformed URL (bad port, unclosed bracket) raises `ValueError`, and every caller that canonicalises search hits drops that hit with an `errors` line naming it — one bad hit never fails a node (orchestrator ruling, WP-B review); `domain(url)`; `registrable_domain(url)` (last two labels, plus a small second-level set such as `co.uk`, `com.au`, `ac.uk`).
- `engines/ledger.SpendLedger` (thread-safe): `take(kind, n=1) -> bool` (atomic check-and-count against the cap for `kind ∈ {fetch_first, fetch_gap, fetch_extend, exa_search_first, exa_search_gap, exa_search_extend, exa_contents_pages}`), `count(kind, n=1)` (uncapped counters: `exa_text_pages`, `arxiv_queries`, …), `add_usd(x)`, `snapshot() -> dict` (the node thread writes it to `search_spend` after each wave). Pinned sources never call `take` — not for the fetch and not for an `exa_contents` page; they `count` what they use, so their spend stays visible and no cap can refuse them. When a pinned and an unpinned copy share a canonical URL, the pinned copy wins the dedupe (WP-B review).
- `engines/fetchers.fetch(source, *, cfg: FetchConfig, ledger, exa_enabled) -> FetchResult(ok, markdown_path, title, chars, fetcher, ms, error, rungs_tried)`: chain filtered by availability at import (`intel_*` only when both `INTEL_*` paths exist); **SSRF guard** — `native` and `exa_contents` refuse URLs whose host resolves to loopback, private (RFC 1918), link-local or the server's own ports (the proxy admin UI, the console), recorded as `error="refused: private address"`. The request goes to the address the guard checked — no second DNS resolution (per hop: connect to the checked IP with the original `Host` header and TLS `sni_hostname`), so DNS rebinding cannot swap the target — except through an HTTP(S) proxy taken from the environment, where the request goes by host name (the proxy resolves; the guard's checks still run first; residual risk recorded in the WP-B note); IPv4-mapped, IPv4-compatible (`::a.b.c.d`) and NAT64 (`64:ff9b::/96`) addresses are judged by their embedded IPv4; a backslash in a `http(s)` URL is read as `/` (WHATWG) before the host is taken, for every rung including `intel_*`; own endpoints are compared by normalised host (lowercase, trailing dot stripped) and port — not by resolved address: a public endpoint's address is shared (CDN, tunnel edge) and would refuse unrelated sites, and a private one is refused by the private-address rule anyway (WP-B fix round 2). Byte cap `cfg.max_bytes` on every download, measured on the **decoded** bytes as they are produced: requests send `Accept-Encoding: gzip, deflate`, bodies are decoded by a bounded decompressor, any other `Content-Encoding` is refused. A rung raises its own error type for expected failures (HTTP status, network, refusal, size, a third-party parser's exception — recorded with the exception type); any other exception propagates. `rungs_tried` keeps every failed rung's error even when a later rung succeeds, and the fetched item carries it (WP-B review); `native` by URL class (arXiv → ar5iv HTML via trafilatura, PDF via pypdf inside the rung; GitHub repo → raw README; `.pdf` → pypdf; else trafilatura `extract(html, include_links=False, favor_recall=True)`); `exa_contents` → `POST https://api.exa.ai/contents` counting pages and `costDollars`.
- `engines/search.run_wave(queries, *, cfg: SearchConfig, ledger, recency, mode) -> (hits, errors)`: per-mode Exa budget via the ledger; `exa_text_pages` counted; arXiv serialised (`threading.Lock` + `min_interval_s`, ≤ `max_queries_per_run`); `github_mode`; recency only for `time_sensitive` briefs (`startPublishedDate` for Exa; `timelimit` for DDGS; `sortBy=submittedDate` for arXiv) with `dropped_undated` counted; canonical dedupe.
- Quote verification (`research.py`, verbatim, B4): normalise the document and the quote alike — case, whitespace, quote marks, dashes, markdown links/images → their text, footnote markers (`[n]`), ordered-list and blockquote (`>`) markers at line starts; `<=` `>=` `!=` → `≤` `≥` `≠` — and split into tokens: whole numbers (a sign when not preceded by a word character, `.`/`,`/`:` only between digits, a trailing `%`; a number glued to letters — `50M`, `2nd`, `10x` — is one word token, so "$50" ≠ "$50M"), the symbols `< > ≤ ≥ ≠ ± =`, and words (`\w+`), so "0.5%" ≠ "5%", "-5%" ≠ "5%" and "≤" ≠ "≥". A quote verifies when its tokens occur **contiguously and in order** in the document's tokens, the first segment not starting right after a negator (`not`, `never`, `cannot`, `without` and the `n't` contractions) — an excerpt may not cut a negation off; an ellipsis (`...`/`…`) splits the quote into segments that must each occur contiguously, in order, each starting within 3 000 characters (of the normalised token text) of the previous one's end; a quote with more than 8 segments does not verify (bounds the work). Nothing else is tolerated: a substituted, added or dropped word or number fails — a changed figure, a swapped entity, "at most" → "at least", a dropped "not". `None` when there is no quote. (Orchestrator ruling, WP-B re-review: replaces the anchored fuzzy match, whose token-set check still let substitutions through; replayed on 649 real quotes from five runs on 2026-10-19, the verbatim rule verified no fewer quotes — it bridges ellipses the fuzzy match could not. `quote_verify_fuzzy` is removed. Number/symbol tokens, the negator guard and the segment cap followed the third re-review — replayed on 643 real quotes from five runs, they keep 623 of the 625 quotes the plain word rule verified.) Performance bound (test): ≤ 50 ms per 250-char quote on a 60 000-char document.
- Allocation (`graph/outline.py`): a note may sit in **at most 2 sections**; deterministic repair of the LLM's allocation — drop unknown ids, give each unallocated note to the section with the most `sub_qs` overlap, cap per-note membership at 2; a section with fewer than `section_min_notes` notes is **merged into its neighbour** (the previous section, else the next), never dropped (R11). Extend mode as in Phase C (titles immutable, ≤ 1 new section for a starved sub-question, `changed_sections`). The titles `TL;DR`, `Sources` and `Analysis` are reserved: the outline prompt says so, and compose renames a section titled `Analysis` (casefold) to `Evidence analysis` in the outline it returns.
- Analyst input (R12): the per-section **findings** (claim + `[ids]` + section), the deterministic `stance_map`, coverage, the note index (id, title, registrable domain, authority, published) — not the raw section bodies.
- Confidence label (R13): D = distinct **registrable** domains among cited sources with authority ≥ 1; V = at least one `quote_verified` claim among the cited notes of authority ≥ 1 whose text overlaps the takeaway (≥ 2 shared non-stop words) — authority-0 sources count for neither D nor V; A = max authority; **contradiction cap**: if any note on the takeaway's sub-questions has `stance == "contradicts"`, the label is at most `medium` and the reasons include `"contradicted by [n]"`. `high` if D ≥ 2 and V and A ≥ 2; `medium` if (D ≥ 2 and (V or A ≥ 2)) or (A ≥ 2 and V); else `low`.
- Gap signal (R14): `coverage_gaps` = sub-questions with `coverage[k] < coverage_min_strong` **or** allocation-starved (no section owns them), first; the coverage judge's `missing_sub_qs` second; **zero-yield stop**: a sub-question whose last gap wave added 0 strong notes (from `gap_history`) is not researched again; when no eligible gap remains, `next` skips `"research"`.
- Judging (R1): the grounding judge runs in **batches of ≤ `judge_batch_size` findings grouped by section**, each batch given exactly its cited notes' claims with full quotes (≤ 250 chars) — never the truncated whole-evidence block; **input bound**: ≤ 3 claims per cited note, chosen by word overlap with the batch's findings, and a batch prompt budget of 24 000 chars — a batch over budget is halved until it fits (so a small rerouted model never overflows); batches run on the panel pool; `PanelVerdict.judged/total` recorded; a batch that fails, times out or returns unparseable JSON counts its findings as **unjudged, never as passed** (v3 counted a failed judge as a pass: baseline b1 (unquoted id in the JSON) and b3r (429) shipped "0 flagged" that way); the live check requires `judged == total`; any unjudged finding → banner "⚠ Not fact-checked — <k> of <n> findings were not judged (<reason>)". Ids in the judge's reply are normalised (`[f3]`, `F3`, `3`, a `finding_id` key → `f3`); an entry that still names no finding of its batch makes the reply unparseable (retried, then the batch is unjudged). Twin findings take the **stricter** verdict: a kept twin of a cut finding is cut too — the analyst restates section findings by design, and a judge that disagrees with itself must not leak cut content (live q013: a reworded claim cut in its section reached the TL;DR through its kept analysis twin at similarity 0.68). Two findings are twins when either (i) they are ≥ 0.85 similar (the dedupe rule) with the same numeric values and neither negates what the other asserts (exactly one of them containing a negator token → not twins), or (ii) they carry the same set of ≥ 2 distinct numeric values and share a cited source — negators ignored, since a restatement often adds a caveat ("… and these should not be attributed to Nebulon AI", live q013). Numeric values: numbers not attached to a name (`GPT-4`, `H2`, `v0.2`, `Qwen2.5-72B` are names), a hyphenated range read as both its bounds (`10-20%` → 10 and 20), thousands separators removed, compared by value — `30%` = `30 percent`, `15.5x` = `15.5×`, `$1,200` = `$1200`, `70B` = `70 billion`; a different value makes a different claim; no sign is read. Known limits (all over-cuts but the last two): same-number claims about differently numbered names (`GPT-4` / `GPT-5`), antonyms ("rose 5 %" / "fell 5 %"), signs, rule (ii) on different claims sharing a study's context numbers and source, rule (ii) on a claim and its negation when they share ≥ 2 values and a source, and rule (ii) on different claims whose only numbers are one shared range or date ("the Oct. 27-28 meeting" → 27 and 28; an ISO date `2024-10-20` reads 2024 and 10); a name written with a space instead of a hyphen (`Llama 3` / `Llama-3`) and a range spelled out in words ("ten to twenty percent") do not twin.
- Cutting (B1): the extractor returns `Finding.sentence` (verbatim); cut by normalised containment of `sentence` in the section/analysis markdown, else `difflib` ratio ≥ 0.85 over a window of **1–3 adjacent sentences** (measured on the probe's 37 findings: 1–3-sentence windows locate 35, incl. the condensed hallucination f6 at 0.93; 2–3 only locate 27; single sentences 34 and miss f6); cuts remove **whole sentences only** and drop a paragraph left without one (baseline b3r opened with an orphan fragment after a string cut); a finding whose citations are all unknown ids (no such source) is cut deterministically with reason `unknown source id` (no judge needed — baseline b0 carried 21 `【n†…】` markers over 8 ids, 7 with no Sources entry); unlocated flags are listed as "flagged but not located (still in body)" **and counted as in-body by the metric**. Location order: whole normalised sentences equal to `sentence` (every aligned occurrence in the section is cut), then containment, then the window; a finding whose sentence lies inside a cut span is cut too (reason `stated in a cut sentence (f<n>)`); an unknown id cited beside known ones is stripped from the kept sentence with a `cite:` errors line. Judge reasons rendered in the report escape square brackets (a reason quoting a printed list `[42, 42]` is not a citation); footnote-definition lines (`[^n]: …`) in writer output are removed with a `cite:` line; `cite:` lines appear in the degradation notes (not counted as degradations). Evolves `quarantine.py`'s splitter/locator/mover (kept); the legacy string branch in `report_builder` is removed when this lands (it cut the TL;DR in baseline b1).
- TL;DR (R2, deterministic, after the cuts, in `report_builder`): analyst on → the top ≤ 4 **kept** takeaways (a takeaway is kept only when its analysis finding is `kept`) with their labels; analyst off/omitted, or no takeaway kept → the first kept finding sentence of each section (≤ 4); nothing kept → omitted (degradation note); a section finding enters the TL;DR only when its sentence is contained (normalised) in the cut markdown — never by fuzzy match. Labelled "_TL;DR — compiled from the report's own cited, judged findings_". No LLM TL;DR exists in v4.
- `graph/assemble.assemble_draft(*, tldr, sections, analysis_md, appendices=None, fetched, flat, tldr_heading="TL;DR") -> str` (lecture passes `"Executive TL;DR"`): TL;DR → sections [flat: `## Findings` + body] → `## Analysis` → appendices → `## Sources` **built over body + appendices** (R22); `normalize_cite_markers` handles `【n】`, `［n］`, `〔n〕`, `【n†…】`, `[n, m]`, ranges `[1-3]`/`[1–3]`, `[^n]`, `[Source n]` → `[n][m]…`.
- `graph/precision.scan(md) -> list[str]` (sentences with numbers/%/currency/years/dates and no `[n]`) → the `## Uncited specifics` appendix and the `uncited_specifics` metric only. **No inline `[uncited]` body markers**: the scan is a heuristic (it tags years, versions and dates in otherwise cited prose) and a marker the reader learns to ignore costs trust; inline marking is **optional / later** behind a knob if a measured need appears.
- `panel_node` writes `panel_verdict.next`; `route_after_panel` returns it. Degradation/skip/legacy error strings carry a round tag `[r<k>]` with `k = 1 + revise_rounds + extend_rounds`; the degradation notes show the current round and collapse earlier rounds to a count.
